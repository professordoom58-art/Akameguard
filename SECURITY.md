# Security policy

## Reporting an AkameGuard vulnerability

Please do not publish exploit details, credentials, working web shells, or
weaponized payloads in a public issue.

If you find a security vulnerability in AkameGuard itself, report it privately
to the project maintainers through the security contact configured for the
repository. Include:

- A short description of the affected component and version.
- Reproduction steps using harmless marker data where possible.
- The impact and any configuration needed to reproduce it.
- A suggested fix, if you have one.

If no private security contact is configured yet, open a minimal public issue
asking for a private reporting channel without including exploit details.

## Scope

This policy covers AkameGuard's scanner, integrity monitor, hardening checker,
runtime files, tests, packaging, and documentation.

AkameGuard is not a replacement for secure application design, timely updates,
strong credentials, least-privilege file permissions, or tested backups.
